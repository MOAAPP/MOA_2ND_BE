# 변동지출 예측 고도화 (3단계) 및 그래프 API (4단계)

생성: `python -m app.ml.train` → `app/data/models/evaluation.{json,md}` (모델 파일은 gitignore 대상, 배포 시 재학습 필요).
조회: `GET /api/v4/ml/evaluation` (요청 시 재학습하지 않고 저장된 보고서 반환).

## 무엇을 바꿨나
- LightGBM을 **다중 호라이즌**(1~14일 앞)으로 학습. 기존에는 학습 예제가 전부 "하루 뒤"였는데 추론은 1~14일 뒤를 예측해서 `days_from_origin`이 학습되지 않았음.
- 금액 특징을 사용자 평균으로 나눠 정규화하고 `지출/사용자평균`을 Huber 손실로 학습 → 사용자 간 규모 차이를 흡수.
- 베이스라인 3종: 전체 평균(`overall`), 최근 7일 이동평균(`recent7`), 요일별 평균(`weekday`). 모든 모델이 **동일한 관측 완료 사례**로 평가됨.
- 지표: 기간 합계 MAE·RMSE·편향, 일 단위 MAE·RMSE, 잔액 오차/자금부족 놓침·오경보(proxy).
- 모델 선택은 검증 구간 7일 MAE 기준(현재 `overall`). LightGBM이 검증에서 이기지 못하면 서비스 기본 모델로 쓰지 않음. 그래프 API는 `model=lightgbm` 기본값으로 LightGBM을 항상 직접 호출해 보여 줌.

## 결과 해석 (정직한 요약)
- **일 단위 오차는 LightGBM이 가장 작다** (테스트 일 MAE: LightGBM 11,775 < 요일평균 12,714 < 전체평균 12,850 < 최근7일 17,409, 7일 호라이즌).
- **기간 합계 MAE는 전체평균/요일평균이 더 낫다** (테스트 7일: 46,192 / 45,814 vs LightGBM 53,271). 이유: LightGBM의 합계 편향이 -38,169원으로 더 크게 과소예측.
- 원인 1 — **지출 수준의 시간적 상승**: 사용자 평균 대비 일평균 지출 비율이 학습 0.951 → 검증 1.002 → 테스트 1.080으로 상승. 학습 구간만 본 모델은 계속 낮게 예측. (보정 계수는 학습 데이터에서 ≈1.0이라 모델 자체 편향이 아님.)
- 원인 2 — **고지출일(평균의 1.5배 초과) 과소예측**: 모든 모델이 하루 평균 약 4만 원 낮게 예측. 최대 오차 사례는 모두 10/21~10/28 기준의 40만 원대 급증 주간(S17, S15, S01, S20).
- 14일 호라이즌은 사용자당 기준일이 1개뿐(16 사례)이라 통계적 의미가 약함.
- 합성 데이터 55일 기준이며 실제 사용자 성능을 의미하지 않음. 시도했으나 채택하지 않은 것: L1/L2 손실, 잔차 타깃, 평균 보정, 베이스라인 블렌딩(검증에서 모두 베이스라인을 넘지 못함).

## 경고

- 55 observed synthetic calendar days; overlapping test origins are not independent
- 14-day test can contain only one origin per user (16 cases)
- balance warning metrics compare identical scheduled obligations + realized variable outflows (proxy)
- 25% upper scenario is uncalibrated assumption, not a probability or prediction interval
- synthetic evaluation never demonstrates real-user performance
